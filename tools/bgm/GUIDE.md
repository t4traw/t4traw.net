# ループBGMスタジオ 作曲ガイド（仕様と記録）

> 2026-10-01 に t4traw.net へ移植したときに、Claude のプロジェクトで使っていた `bgm-composer-guide.md` を取り込んだもの。
> 「1. ファイル」「2. 依頼を受けたときの進め方」は移植前の体制（単体HTMLが正本）の説明なので、ファイル構成とコマンドは [README.md](./README.md) を優先すること。

自作ゲームのBGMを、会話しながら「ループBGMスタジオ」で作るためのガイド。
このファイルと `loop-bgm-studio.html` と `bgm-tool.js` があれば、どのセッションからでも続きができる。

## 1. ファイル

| ファイル | 役割 |
|---|---|
| `loop-bgm-studio.html` | スタジオ本体。**エンジンの正本**。ブラウザで開けば単体で動く（ローカルでもOK） |
| `bgm-tool.js` | HTML内のエンジンをNode.jsから直接使うCLI。レシピコードの生成・解読・検証・タネ選び・MIDI書き出し |
| `bgm-composer-guide.md` | このファイル。仕様、方針、作った曲の記録 |

`bgm-tool.js` はHTMLからエンジン部分（`const PC=[` から `audio graph` コメントの手前まで＋`partGain`）を切り出して `vm` で実行している。スタジオを改修してもツールは基本的に直さなくていい。ただしこの2つの目印を消さないこと。**状態に新しい項目を足したときだけ**、ツールの `defaults()` と `check` の比較項目に追加する（v5で `bassArr drama arrange`、v6で `drumBusy drumFill`、v7で `drumPlay drumFeel` を追加済み）。

## 2. 依頼を受けたときの進め方（Claude向け）

1. どの画面・場面の曲か、どんな気分か、長くプレイされるかを確認する（聞かなくても分かれば聞かない）
2. 下の「曲調一覧」から近いものを選び、テンポ・キー・音色・メロディ設定を決める
3. ナレッジの2ファイルをコンテナに置き、`node bgm-tool.js seeds '<json>' --top 3` でタネ候補を出す
4. `describe` で内容を確認し、`check` で検証してからコードを渡す
5. ユーザーはスタジオの「レシピコード」欄に貼って「読み込む」で試聴する
6. 決まった曲は「7. 曲の記録」への追記を提案する

**大事な前提**：Claudeは音を聴けない。タネは「歌いやすさの目安」で機械的に選んでいるだけなので、渡すときは「ピンとこなければメロディだけ引き直して」と添える。テンポ・編成・キーなど**設計の意図**のほうをしっかり説明する。

関連する曲どうしは**キーをつなげる**と一体感が出る（例：スタート前とゴールを同じキーに）。緊張を上げる曲は**同じ進行のまま全音上げ＋テンポ上げ**にすると「同じ曲がギアを上げた」ように聴こえる。

### CLIの例

```bash
node bgm-tool.js list
node bgm-tool.js describe 1I1MYKBI2TF-C6R2398D7WB-2UJIB8GS094
node bgm-tool.js encode '{"preset":"midnight","bpm":118,"key":3,"mel":{"counter":true}}'
node bgm-tool.js seeds '{"preset":"longrun","bpm":126,"lead":"marimba","scale":"penta"}' --from 1001 --count 300 --top 3
node bgm-tool.js midi <code> out.mid
node bgm-tool.js check <code>        # ぶつかり度も表示
node bgm-tool.js omakase --count 5   # 「ぜんぶおまかせ」と同じ規則で案を出す
```

`encode` / `seeds` のJSONは省略した項目に**その曲調の既定値**が入る。指定できるキー：
`preset lead pad bassStyle drums key(0-11) scale swing(0-100) bpm(52-176) sections(1/2/4) density tone peak(0-3) seed mel{dens range leap oct(-1/0/1) octUp harm counter} mute{lead chord bass drum} partVol{lead chord bass drum} bassArr(0-100) drama(0-100) arrange(0-100) drumBusy(0-100, 既定55) drumFill(0-100, 既定50) drumPlay(0-100, 既定50) drumFeel(0-100, 既定35)`

### メロディの表情

- 音数 `mel.dens`：0で32小節に約49音、100で約120音
- 音域の幅 `mel.range`：7〜29半音
- 跳ねぐあい `mel.leap`：隣接音の平均が約1.9〜3.6半音
- 高さ `mel.oct`：±1オクターブ
- 重ね：`octUp` オクターブ上 / `harm` ハモリ（コード内で2つ下）/ `counter` 裏メロ（隙間を低い音域で）

### アレンジ（v5）

3つとも0で元の形のまま（v4以前のコードは0として読まれ、演奏も完全に同じ）。それぞれ専用の乱数列を使うので、動かしてもメロディは変わらない。

- **ベースの崩し** `bassArr`：経過音（長い音を2つに割って和音の音へ）、オクターブ跳び、小節の最後で次の根音への寄り（半音・全音）、4小節目の後半を次の根音へ向かうフィルに置き換え（25超）。小節頭の根音は必ず残す
- **伴奏のドラマ** `drama`：前の和音に一番近い形で次の和音を積む（共通音、たとえば3度がそのまま残る）。8小節フレーズの前半は3度と7度だけのシェル、後半は一番上の音のオクターブ上を重ね、ベロシティも前半弱く後半強く。45超でフレーズの区切りに次の和音を8分先取り
- **曲の展開** `arrange`：8小節ごとにエネルギーを割り当て（32小節なら 中→高→低→高）、低い部分はドラム・ベース・伴奏の裏拍・重ねた線を間引いて音量を落とす。区切りにはドラムのフィル、55超で次が盛り上がる手前に短いブレイク（ドラム・ベース・伴奏を2つの8分だけ止める）

使い分けの目安：本編は崩し・ドラマ控えめ（〜40）で展開0〜30、タイトルやリザルトはドラマ・展開を強めに。展開を上げると「ループの頭で少し静かになる」ので、流しっぱなしの画面ではつなぎ目の印象も確認すること。

### ドラムの手数・展開（v6）

キットごとの型（今までの雰囲気）は残したまま、その周りに足していく。0で旧来の型そのもの。**新しく作る曲は 手数50・展開40 が既定**（古いコードは0として読まれ、旧来の音のまま）。

- **手数** `drumBusy`：バックビートのスネア（15〜）、ハットの補い（30〜、カチカチ・夜・そっとのようなスカスカのキット）、軽いキック（35〜）、裏拍のゴーストノート、小節末のオープンハット（25〜）、4つ打ちは50〜で裏拍をオープンハットに（ハウスの定番）、コンガ（40〜、ブラシ・夜・カチカチ・ボサノバ・そっと）、人間っぽい強弱のゆらぎ
- **展開** `drumFill`：4小節目のキックの変化、4小節ごとの小さなフィル（30〜）、8小節目の後半をタムの駆け下り（25〜。ボサノバ・そっとはコンガ、カチカチはリム、4つ打ちはスネアロール）、フレーズ頭のクラッシュ（45〜、ポップ・4つ打ち・ハーフタイム・ブレイクビーツ・ファンクのみ）、フレーズに沿った強弱
- キットごとの設定は `DRUM_STYLE`。新しいキットを足したらここにも1行足す（無ければ手数・展開は効かない）
- 追加した音：snare（ノイズ＋胴鳴り）/ ohat オープンハット / crash / tom（6段）/ perc コンガ（hi・mute・lo）。MIDIはGMの 38 / 46 / 49 / 41〜50 / 62〜64
- 「曲の展開」のフィルと重なる小節では、ドラム側のフィルを優先する
- 1小節あたりの打数（手数50・展開40）：カチカチ 5→13、夜 6→15、そっと 6→14、ブラシ 11→17、4つ打ち 13.5→15。なしは0のまま

### ドラムのグルーヴ・遊び・ノリ（v7）

- **グルーヴ** `GROOVES`：1小節16ステップの文字列（3拍子は先頭12）。`X`アクセント `x`普通 `o`弱 `g`ゴースト `?`手数しだいで鳴る `O`（ハット行の中で）オープン。`a` 基本の小節、`b` 返しの小節（展開>0で4小節目や偶数小節に）、`opt` は手数が `min` を超えると加わるレイヤー。`sw` 固有の16分ハネ、`lay` スネアの後ノリ、`gain` 全体の強さ、`fills` 使うフィル、`crash` フレーズ頭のシンバル
- 声部：k キック / B 808 / s スネア / c クラップ / r リム / h ハット / O オープンハット / S シェイカー / t タンバリン / R ライド / cb カウベル / bl ウッドブロック / p・pl コンガ（高・低）
- **フィル** `renderFill`：tomDown / tomUp / snareRoll（最後4つは32分）/ snareBuild / kickSnare / flamTom / stop（止めて拾う）/ hatBark / hatRoll / triplet（3連の食い＝3対4）/ percRun / rimClick / cowbellCall。置き場所は `placeFills`：8小節目は半小節〜1小節、4小節目は1拍。**遊びが0より上ならループ最後の小節は必ずフィル**（毎周の「入り」）
- **遊び** `drumPlay`：フラム・ドラッグ、次の小節への食いキック、オープンハット、32分のハットロール、ゴーストの連打、カウベルやブロックの一発、**メロディが半小節休んでいるところにパーカッションの合いの手**
- **ノリ** `drumFeel`：16分のハネ（グルーヴ固有の値に上乗せ）、スネア・クラップ・リムを少し後ろへ、人の手の揺れ
- 旧キットは遊びかノリが0より上のときだけこの経路に入る（フィルは `OLD_FILLS` から）。0なら v6 までとまったく同じ音
- 足した音：boom 808（GM35）/ ride（51）/ tamb（54）/ cowbell（56）/ block（76）
- 曲調の既定ドラムを更新：ファンク→16ビート・ファンク、ロングラン→ハウス、ネオン→ディスコ、ブルー→ジャズ、ちいさな冒険→ピコピコドラム、メロウ→ローファイ、たびだち→アフロ、おみせ→ボサノバ、どっしり→ブームバップ（既定は曲調を選んだときだけ効く。コードにはキットが入っているので過去の曲は変わらない）
- グルーヴを足すときは、`KITS` の末尾に名前、`GROOVES` にパターン、`OMAKASE.kit` にエネルギー、4拍子専用なら `only4.kit` に追加

### ぜんぶおまかせの規則

完全ランダムだと約27%が「和音とぶつかる」組み合わせになっていたので、次の規則の中から選ぶ。

- **ぶつかり度** `clashScore`：主旋律と重ねた線の音が、鳴っている和音の構成音でもテンション（EXT）でもなく、構成音の半音隣にいる割合（半音上=1、半音下=0.6、その他の非和声音=0.25、拍の強さと長さで重み付け）。0で完全に和音に沿う
- 音階は、その曲調の既定音階のぶつかり度＋5（最低18）以下になるまでタネ・音階・重ねを引き直す（最大40回）。ブルーやファンクのように元からこすれを狙う曲調は上限も高い。全音音階はおまかせでは選ばない
- 曲調と部品に「落ち着き0／中間1／駆ける2」を付け、重なるものだけ選ぶ（各パート4割は曲調の既定）。3拍子では4つ打ち・ボサノバ・ブレイクビーツ・ファンク・ハーフタイム、ファンクベースを使わない
- はねは曲調の値±12（まっすぐな曲調はほぼまっすぐのまま）、BPMは曲調の±10%、メロディの1オクターブ下は伸ばす伴奏と絡むのでまれに、重ねる線は最大2本
- 結果：2000件でぶつかり度が上限を超えるものは0%（旧方式26.8%）、中央値11→2、拍子違いのドラム0件

### パート音量

`partVol` 0〜100。80が等倍、100で+6dB、0で無音。書き出し音源にもMIDI（CC7）にも反映。`mute` は鳴らす／止めるの切り替え。

## 4. 書き出しの方針（決定済み）

- **既定は「CAF・無劣化」**（16bit PCM, big-endian）。iOSでそのまま鳴り、ループ点にパディングが入らない
- **出力レベルは既定でピーク −3 dBFS** に正規化。合成直後は −9〜−13 dBFS と小さく、アプリ側の音量50%と端末音量が重なってノイズが目立つ、というフィードバックを受けて決めた。試聴用の音量スライダーは書き出しに影響しない
- **ALAC**は `afconvert -f caff -d alac in.caf out.caf` でApple純正に任せる。ブラウザで手書きしたALACより確実に小さく、壊れる心配がない
- **CAF・軽量（IMA4）**は容量1/4だが量子化ノイズ（SNR約39dB）が乗る。静かな曲では非推奨
- ループの継ぎ目：残響の尾を先頭に折り返し、長さを64フレームの倍数にそろえてある
- ファイル名：`loop-<曲調>-<BPM>bpm-<小節>bars-<レシピコード>[-lossless|-ima4][-mono].<拡張子>`。音源だけ見つかってもコードで完全に復元できる
- MIDI：フォーマット1、Melody / Layers / Counter / Chords / Bass / Drums(ch10) に分かれ、テンポ・拍子・GM音色・スウィング・CC7入り

## 5. レシピコード仕様

全設定を16進の固定幅フィールドに詰めて BigInt で base36 にしたもの。先頭ニブルがバージョン。先頭ゼロを除いた16進の長さがレイアウト長と一致することで判別する。

| ver | 16進桁 | 追加された項目 |
|---|---|---|
| 1 | 29 | 初版（曲調・音色・BPM・長さ・にぎやかさ・まるさ・メロディ・重ね/ミュートのフラグ・タネ） |
| 2 | 33 | キー・音階・はねかた |
| 3 | 41 | パート音量 ×4 |
| 4 | 42 | 曲調欄を2桁に（20種を超えたため）。表示は33文字 |
| 5 | 49 | メロディ音色欄を2桁に、ベースの崩し・伴奏のドラマ・曲の展開（各2）を追加。表示は38文字 |
| 6 | 53 | ドラムの手数・展開（各2）を追加。表示は41文字 |
| 7 | 58 | ドラム欄を2桁に、ドラムの遊び・ノリ（各2）を追加。**現行**。表示は**9文字ごと**にハイフン、45文字 |

フィールド順（v7）：ver(1) 曲調(2) メロディ音色(2) 伴奏(1) ベース(1) ドラム(2) BPM(2) 長さ(1) にぎやかさ(2) まるさ(2) 音数(2) 幅(2) 跳ね(2) 高さ＋出力レベル(1: 下位2bitが高さ+1, 上位2bitがピーク) フラグ(2: octUp,harm,counter,muteLead,muteChord,muteBass,muteDrum) タネ(7) キー(1) 音階(1) はね(2) パート音量×4(各2) ベースの崩し(2) 伴奏のドラマ(2) 曲の展開(2) ドラムの手数(2) ドラムの展開(2) ドラムの遊び(2) ドラムのノリ(2)

**互換を守るルール**
- 曲調・音色・ベース・ドラム・音階は**配列の添字でコード化**している。追加は必ず**末尾に**。途中の差し替えや並べ替えをすると古いコードの意味が変わる（かけあがり→おみせ、わふう→もくもくの差し替えで一度やった。古いコードの添字5と10は新しい曲調で読まれる）
- 新しい項目を足すときは新バージョンのレイアウトを作り、古いレイアウトは消さない
- 1桁フィールドは最大16種。超えるなら曲調と同じく新バージョンで2桁に広げる（伴奏・ベース・音階はまだ1桁）
- スタジオは常に最新バージョンで書き出す。v5のコードは v4 以前のHTMLでは読めない（古いHTMLは「読めないコード」になる）
- 新しい項目は「0（または既定値）のとき以前と完全に同じ演奏」になるように作り、乱数は既存の列を消費しない専用の列を使う

## 6. ユーザーの好み・決定事項

- 用途は自作iOSゲームのBGM。**ゲームBGMとして合うか**が判断基準。和風（わふう）や過度に煽る小室進行（かけあがり）は合わないとして外した
- 長くプレイされる画面は「耳が疲れない」ことを優先。本編はドラム控えめ、メロディはやわらかい音色に寄せる
- 公開してアプリの利用者にも使ってもらう予定。UIは「パート名 → 楽器 → 🔊 → 音量」の1行構成。フッターの技術的な説明は削除済み（残しているのは「ループのつなぎ目」「権利」のみ）
- 生成物はすべてオリジナルで商用利用可。既存曲（例：Wii の Mii チャンネル）に似せる依頼でも、空気感だけ参考にしてコピーはしない

### スタジオを改修するときの確認手順

1. `node --check` で構文
2. 全曲調 × ベース × ドラム × 音階の組み合わせで、ループ範囲外のイベントや音域外の音がないこと
3. レシピコードの往復（ランダム数千件）と、**過去バージョンのコードが読めること**（下の記録のコードを使う）
4. 書き出し形式はffmpegでデコードして確認（CAF無劣化はWAVとビット一致、IMA4はSNR約39dB）
5. Playwright（コンテナに入っている）で全曲調クリック・おまかせ連打・レシピ読み込みを通し、ページエラーがないこと
